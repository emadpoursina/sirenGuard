- **Main process files**: lowercase, no dashes (e.g., `main.js`, `preload.js`, `store.js`)

## File Organization

### Project Structure

```
main.js       # Electron main: tray, window, lock IPC
preload.js    # contextBridge IPC bridge
store.js      # electron-store wrapper
renderer/     # floating button UI (index.html, button.js, style.css)
assets/       # tray icon, button glyph
```

### Conventions

- **Main process logic**: lives in `main.js`, grouped by concern (window creation, tray, IPC handlers) as top-level functions
- **Persistence**: isolated in `store.js` behind small getter/setter functions — never touch `electron-store` directly from `main.js` or renderer
- **IPC surface**: only exposed through `preload.js`'s `contextBridge`; renderer never uses `ipcRenderer` directly

## Import Order

```javascript
// 1. Node built-ins
const path = require('path');
const { exec } = require('child_process');

// 2. Electron
const { app, BrowserWindow, Tray } = require('electron');

// 3. Local modules
const { getButtonPosition, setButtonPosition } = require('./store');
```

**Rules**:
- Group requires: Node built-ins, then Electron, then local modules
- Use CommonJS (`require`/`module.exports`) — no ESM/`import` syntax
- Destructure only what's needed from each module

## Error Handling

### Pattern

**Approach**: Defensive try/catch around OS-level or Electron API calls that can fail (e.g., `app.setLoginItemSettings`), falling back to stored/default state

### Guidelines

- Never let a failed OS-level call (login items, lock command) crash the app
- Prefer silent fallback to stored preference over throwing
- Keep catch blocks minimal — no logging infrastructure exists yet

### Example

```javascript
try {
  app.setLoginItemSettings({ openAtLogin: enabled, openAsHidden: true });
  setLaunchAtLogin(enabled);
  return true;
} catch {
  return false;
}
```

## Code Patterns

### Preferred Patterns

#### Getter/setter wrappers around persistence

Isolate all `electron-store` access behind named functions in `store.js`.

```javascript
function getButtonPosition() {
  return store.get('buttonPosition');
}
```

### Anti-Patterns to Avoid

- **Rewriting whole files**: Never rewrite an entire file to change one function — surgical edits only
- **New dependencies**: Don't add packages without explicit approval
- **Direct `ipcRenderer` use in renderer scripts**: Always go through `contextBridge`-exposed APIs
